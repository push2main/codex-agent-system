# Prompt Rules

- In `agents/planner.sh`, reject or auto-rewrite any step whose text contains `Expected:` plus a claim that the target state already exists (`already`, `already exists`, `already reads`, `confirm`, `inspect only`) when the queue title asks for a code change; classify this as `plan_noop_mismatch` before coder dispatch. This targets the repeated review rejections on `task-004`, `task-006`, and `task-008` where Step 1 only rediscovered that no edit was needed.
- In `agents/planner.sh`, add a preflight gate for edit tasks: if the title matches `add`, `update`, `change`, `document`, `fix`, or `create`, Step 1 must contain exactly one file target and one concrete write verb, and must not exceed 220 chars; otherwise split or fail planning. This is enforceable in the step-scope validator and should reduce review-rejection churn from over-specified Step 1 prompts seen in `task-002`, `task-003`, and `task-007`.
- In `scripts/lib.sh` `classify_retry_failure`, add a deterministic `anchor_mismatch_noop` bucket triggered by reviewer/evaluator text containing `already satisfied`, `already exists`, `no changes needed`, `anchor missing`, or `requested state already exists`; mark it non-retriable at write time. This would have prevented wasted second attempts on at least the repeated planner-comment and learner-comment tasks.
- In `agents/planner.sh`, before emitting any step with a line-number anchor, run a file-anchor validation check: if the referenced file is missing or the referenced line window does not contain one of the quoted anchor strings, fail planning as `missing_source_file` immediately. Enforce this for any step mentioning `line`, `lines`, or quoting an expected comment block; this addresses the repeated `missing_source_file` failures on task families `task-175`, `task-176`, `task-007`, and `task-005`.
- In `agents/reviewer.sh` or the review parser, treat non-schema reviewer output as a hard classification signal instead of generic retry: if reviewer output fails deterministic schema and coder/evaluator both succeeded, classify the step as `reviewer_indeterminate` and do not requeue the same plan unchanged. Recent logs show fallback review plus retry behavior on a successful small task path; codifying this should cut avoidable review-driven retries in the dominant `review_rejection` bucket.
