# Prompt Rules

- In `agents/planner.sh`, reject any self-improve task whose title or failed step text exceeds 220 characters or contains more than 2 clause separators (`--`, `;`, or 3+ commas); rewrite it into an inventory task with exactly 1 file target and 1 expected artifact before execution. This targets the repeated `review_rejection` pattern on oversized multi-constraint prompts and should cut first-step rejections on inventory/fix tasks.
- In `agents/planner.sh`, add a preflight rule for any step containing `Inspect`, `Inventory`, or `identify the narrowest`: the generated plan must be exactly 2 steps max, with step 1 naming one existing file path and one concrete function/branch anchor, and step 2 as verification. If the anchor cannot be named from repo search, classify as `scope_mismatch` and stop. This prevents review rejections caused by vague inspection tasks recurring across 7 inventory tasks.
- In `agents/orchestrator.sh`, if a task is marked `review_rejection` on attempt 1 and the step references more than 1 file, automatically rewrite retry attempt 2 to a single-file version using only the first existing path found in workspace; if no existing path is found, classify `missing_source_file` as non-retriable. This converts a dominant rejection class into enforceable scope reduction and avoids wasting the second attempt.
- In `agents/orchestrator.sh` and `scripts/lib.sh`, add a grounding gate before coder dispatch: for every backticked path in the step text, require `exists_count == referenced_count`; if any are missing, fail before provider call with `missing_source_file`, `retriable=false`, and include the first missing path in the message. This addresses the repeated `missing_source_file` and downstream `review_rejection` loop on nonexistent inventory artifacts.
- In provider routing for `agents/planner.sh`, if `project_local` recent-50 success rate is `0.00` or planner zero-step timeout rate is `>= 0.25`, force the planner to use the provider with the lower 20-run timeout count and cap planning prompts to 1200 characters. The latest task failed with a 60s zero-step timeout, and this rule is a code-enforceable timeout-prevention gate rather than another generic retry.
- **Anti-meta-task rule**: Strategy must not generate tasks about improving the system's own learning loop, metrics pipeline, or strategy generation when recent-50 success rate is 0%. Instead, it must generate only concrete file-edit or test-writing tasks targeting existing source files. Meta-tasks (titles containing "improve", "reduce", "optimize", "inventory", "review signal") are banned until recent success > 20%.
- **Minimum concreteness gate**: Every generated task must reference at least one existing file path AND specify the exact function or section to change. Tasks without a concrete file anchor must be rejected at generation time, not at review time. This prevents the dominant failure mode of vague inspection tasks.
