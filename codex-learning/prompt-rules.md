# Prompt Rules

- In `agents/planner.sh`, add a preflight `detect_noop_anchor_task()` that runs before step generation for comment-only and line-specific edit tasks; if the task text contains `already exists`, `confirm`, `inspect`, or `line ` and the requested target text is already present in the named file, mark the task `non_retriable_review_rejection` and skip coder/reviewer execution. This directly targets the repeated no-op comment tasks that were retried and rejected at least 4 times.
- In `agents/planner.sh`, reject any step-1 instruction longer than `420` characters or containing more than `2` quoted expectations (`Expected:` clauses, parenthetical enumerations, or `line N` anchors); auto-split into `inspect anchor` and `edit` steps, with verification as the final step. This is enforceable in the existing step-scope gate and should reduce review rejections caused by overloaded first-step instructions, which appear across the repeated test/comment failures.
- In `agents/orchestrator.sh`, add a retry guard keyed by `task_title + failed_step text hash`; if a task fails twice with `review_rejection` and the normalized step-1 text similarity is `>= 0.85`, shelve it instead of requeueing. This prevents the observed repeated retries on the same rejected plan shape and should eliminate at least the 2-task churn clusters shown for `classify_retry_failure`, `clamp_prompt_context`, and planner-step-cap tasks.
- In `scripts/lib.sh` inside `classify_retry_failure`, add a deterministic classifier for no-op/anchor-mismatch review failures: if reviewer/evaluator text contains phrases like `already exists`, `already matches`, `no change needed`, `wrong anchor`, or `target already satisfied`, classify as `review_rejection_noop` rather than generic `review_rejection`. Then, in `agents/orchestrator.sh`, make `review_rejection_noop` non-retriable. This improves classification on a dominant failure mode and prevents wasted retries.
- In `agents/planner.sh`, before creating test-file tasks, require an on-disk anchor check: if the task says `model it on`, `following project pattern`, or references an example file, verify that referenced file exists with `[[ -f ... ]]`; if missing, fail planning immediately as `missing_source_file` instead of producing a speculative test step. This addresses the repeated test-task failures where nonexistent anchors and invented filenames led to review rejection or missing-source churn.
