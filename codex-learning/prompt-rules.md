# Prompt Rules

- In `orchestrator` pre-check, if a task is single-file (`files:` has 1 path) and the title/body references the same target file plus 2 or more secondary contract files, rewrite it into a 2-step bounded task: `inventory` then `implement`, and cap writable scope to the single target file only. This addresses the repeated `apps/cloud-brain/scripts/smoke.mjs` review rejections caused by contract-validation tasks expanding beyond one concrete edit site.
- In `build_retry_prompt` and `classify_failure`, when `failure_kind=review_rejection` on a single-file task, require the retry payload to include all 3 fields before requeue: `target_file`, `exact_edit_anchor`, and `rejection_delta` extracted from reviewer text; if any field is missing, generate an inventory task instead of a direct implementation retry. This is enforceable at queue time and should cut wasted review-rejection retries in the dominant category.
- In `task_deduper` or strategy generation, if 2 or more open/recent tasks within 12 hours target the same file and share a normalized stem of at least 5 words after removing verbs like `verify`/`inventory`, suppress new implementation tasks and emit at most one follow-up verification task. The history shows the same 3 smoke-flow themes being regenerated repeatedly; this rule reduces scope churn and prevents redundant retries.
- In `post-guard` and cooldown logic, treat `SUCCESS` with `score <= 32` or `attempts > 1` as `weak_success`: do not activate `recent_success_cooldown` for sibling tasks with the same normalized stem until one explicit verification task passes. Multiple recent tasks succeeded with score `0/31/32`, then still triggered inventory follow-ups; this rule prevents false confidence and improves retry classification quality.
- In the orchestrator step planner, if a task description exceeds 45 words and targets one file, force a maximum of 2 execution steps: `inspect anchor` and `implement or verify`, with reviewer/evaluator required to check only the named anchor. The logs already show verbose-task timeout gating at 59 words; making this deterministic for single-file tasks should reduce timeout exposure and review noise on narrow smoke assertions.
