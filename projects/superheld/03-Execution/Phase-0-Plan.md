# Phase 0 Plan

## Purpose

Phase 0 is the planning and shaping sprint before public repo bootstrap. The goal is to remove ambiguity, reduce avoidable rework, and pick the first slice worth building.

## Exit Criteria

Phase 0 is complete when all of the following are true:

- the mandatory MVP protection cases are locked
- the first implementation slice is chosen
- the repo bootstrap approach is clear
- the telemetry and incident schema outline exists
- the first three playbooks are defined at a high level
- the learning center outline exists
- the verification bar for initial development is written down

## Work Package 1: Product Lock

- finalize target audience for beta
- choose guided recovery versus preventive protection emphasis
- lock the MVP protection cases

## Work Package 2: Repo Strategy

- inspect the current local workspace
- classify areas as keep, refactor, or leave out
- decide the clean first public baseline

## Work Package 3: Technical Baseline

- define telemetry schema outline
- define incident model and evidence shape
- define approval boundaries for response actions

## Work Package 4: First Slice Definition

- choose the first signal source
- define the first end-to-end incident flow
- define test and verification expectations

## Recommended Sequence

1. product lock
2. first slice selection
3. repo strategy
4. schema and playbooks
5. verification bar

## Suggested Deliverables

- one locked MVP scope note
- one repo baseline recommendation
- one schema sketch
- one playbook summary note
- one initial implementation plan

## Suggested Timebox

- 2 to 4 focused planning sessions
- target completion before broad coding or first public push

## Verification

- every planning decision should lead to a specific implementation consequence
- if a note cannot influence code, scope, or launch behavior, it is probably too vague
